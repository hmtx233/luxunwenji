### 接入 Google Analytics 4

用户给了官方 gtag.js 片段（衡量 ID `G-SSJP85LM7Q`）。做法：

- `config.mts` 顶部新增 `const GA_ID = 'G-SSJP85LM7Q'` + `analyticsTags()`
- 在 `defineConfig` 的**静态 `head`** 里 `...analyticsTags()`（紧跟 `verificationTags()`）
- 与站长验证码同构：**ID 留空即完全不输出统计代码**，本地开发/想关掉时改一处即可
- 用官方原版片段：`['script', { async: '', src: ... }]` + 一段内联 dataLayer 初始化
  （VitePress 会把内联脚本压成一行，`gtag("config","G-…")` 引号也变成双引号，
  所以 grep 时别按原始片段的引号去匹配）

**踩到的坑（值得记）**：第一次构建卡在打包阶段 3 分 38 秒没动静，
`dist` 里还是上一轮的产物（时间戳没变）。把构建 kill 掉直接重跑，
**116 秒正常完成** —— 缓存目录当时本来就是空的（`cache` / `.temp` 不存在），
所以这次连「清缓存」都不用，纯粹是重跑就好了。
结论：卡在 `building client + server bundles` 且 `dist` 时间戳不动时，
不要等，kill 掉重跑是成本最低的处理。

**验证**：用 Node 递归扫 `dist`（**别用 bash for 循环**，
学术/书信的文件名带空格会把循环拆断，报 `No such file or directory`），
596 个 html **全部**命中埋点。

`verify-seo.mjs` 新增了埋点覆盖检查：从 `config.mts` 里读 `GA_ID`，
留空则打印「未启用」并跳过（否则关掉统计后校验反而会失败）。

### 需要留意：GA 收不到国内流量

`googletagmanager.com` 在中国大陆通常不可直连，国内访客的会话加载不到该脚本、
不会上报。站点的目标读者又主要在国内，所以 GA 的数字会**严重低估**。
若要覆盖国内流量得另接百度统计 / 51LA 之类，两者可以并存（README 已注明）。
