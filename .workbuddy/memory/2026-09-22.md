## 鲁迅文集站点（luxunwenji.com）

### 1. 修复学术 / 书信首页篇目「点不动」

**症状**：文集首页的「## 篇目」列表里，含空格的那些条目点不动。

**根因**：文件名为中文数字编号且**含空格**
（`第一篇 史家对于小说之著录及论述`、`第一集 北京_一`）。
CommonMark 的链接目标**遇到空白即终止解析**，markdown-it 解析失败后
把整段 `[文字](/路径 带空格)` **当纯文本输出** ——

- 于是根本不是一个 `<a>`，自然点不动
- 更麻烦的是**不触发 VitePress 死链检查**，构建照常通过，属于静默故障

受影响的共 **63 处**（学术 28 + 书信 35），只有这两个文集有空格文件名。

**修法**：链接目标里的空格编码成 `%20`（中文保留明文，与其余 21 个文集一致）。
改 `scripts/reorder-index.mjs` 为统一编码，重跑即修复。
VitePress 输出 HTML 时会把 `%20` 还原成字面空格写入 `href`，
浏览器点击时自动编码，实测死链检查 0 报错、目标 `.html` 均在产物中。

新增工具 `scripts/find-broken-links.mjs`（`npm run lint:links`）全站扫描此类写法。

全站已校验每页 `<h1>` 恰为 1 个。

### 关键教训：构建"卡死"的真因不是残留进程

此前把构建卡在 "building client + server bundles" 十几分钟
归因为「上一轮 build 进程残留」。**实际原因是 `vitepress dev` 与
`vitepress build` 同时运行** —— 两者共用 `docs/.vitepress/cache` 与 `.temp`，
并发互相锁死。用 `tasklist` 查到确实有 `npm run docs:dev` → `vitepress dev docs` 在跑。

绕开办法：`scripts/prepare-verify-build.mjs` 把 docs（约 4MB，跳过 dist/cache/.temp）
复制到 `D:\_lx-verify`，用 junction 链好 `node_modules`，在那里构建，
完全不影响用户正在运行的 dev server。实测 84–88 秒正常完成。

**另一个坑**：删含 junction 的目录前必须先解除链接，
否则 `rm -rf` / `Remove-Item -Recurse` 会顺着链接删掉真正的 `node_modules`。
正确做法 `[System.IO.Directory]::Delete($link, $false)` 只删链接。

**注意**：`vitepress dev` 是客户端渲染，curl 拿到的只是 427 字节的 SPA 外壳，
想在命令行校验必须有 build 产物。

### 4. 一次误判的自我纠正

上一轮我把正文的 `-apple-system / PingFang SC` 字体栈当成
「heti 字体丢失的 bug」并改成了宋体栈。**这其实是用户明确指定的方案**，
`MEMORY.md` 里早已写明（我改前没读到位），改动随后被回退。

现状：`custom.css` = 用户指定的系统无衬线栈 + 我加的结构性样式（表格 / 列表 /
`.about-date`），两者已合并入库。`custom.css` 顶部注释写明

因此也**移除了 `ArticleTitle.vue` 里硬编码的标题字体族**，让它继承。

**教训：改样式前先读 `custom.css` 顶部注释与 MEMORY.md 的"用户指定方案"条目。**

## 第二轮：序文出页 + OG/结构化数据

### 1. 文集首页不再整段照抄序文

**问题**：23 个文集首页里有 17 个把序文全文抄了一遍
（序言/自序/题记/题辞/小引），而同一篇文字另有独立文章 ——
同一内容两个可访问 URL，既重复又稀释首页权重。

**做法**：新脚本 `scripts/build-index.mjs`（取代 `reorder-index.mjs`）统一处理：

1. 丢掉 `## <序文名>` 整个小节，只留「`# 文集名` + 引言 `>` + `## 篇目`」
2. 按 `config.mts` 的 `order` 重建 `## 篇目`，序文作为**第一条**列出（点进去就是独立页）

顺带修正：小说/散文的篇目列表原先按拼音排，与侧边栏的**原著篇序**不一致，
现在两者同源（都取 `order`）。23 个首页全部重建，序文移除 17 处。

**踩到的两个坑**：

- `loadCategories()` 里找数组起点必须先定位 `=` 再 `indexOf('[')` ——
  直接从 `const categories: Category[] = [` 之后找 `[`，会命中**类型标注
  `Category[]`** 自己的方括号，取到空数组（表现为"共更新 0 个"）。
- `stripSections()` 一开始只丢序文、留着旧的 `## 篇目`，结果新旧两段并存
  （页面出现两个「篇目」）。必须在同一步里把 `篇目` 也丢掉再重建。

配套 `scripts/verify-index.mjs`：除序文段与篇目段外，头部内容与备份
逐字一致（去空白归一化），且每处被移出的序文都能在同名独立文章里找到。

### 2. Open Graph / Twitter Card / JSON-LD

原先静态 `head` 里只有两条写死的 `og:type` / `og:site_name`，
**文章页也是 `website`**，且没有 `og:title/description/url/image`。

改为在 `transformPageData` → `buildHead()` 里逐页生成（仍是**直接赋值**，
见坑 1），静态 `head` 里那两条已删（否则同属性出现两次）。

- `og:type`：文章页 `article`（附 `article:section` = 卷名），其余 `website`
- `og:image`：1200×630，每部文集一张；JSON-LD 用单个 `@graph`
  （首页 `WebSite`／文集首页 `Book`／文章页 `Article` + `isPartOf: Book`／
  非首页附 `BreadcrumbList`）

**顺带修掉一个真 bug**：`transformPageData` 里 `relativePath` 对文集首页是
`xxx/index`，拼 `${SITE_URL}/${relPath}` 会生成 `/xxx/index` 这个 404 地址
当 canonical。现在文集首页输出 `/xxx/`（带尾斜杠），文章页不带，
且**按路径段百分号编码**，与 sitemap 的写法一致（原先 canonical 是明文中文，
sitemap 是编码的，两处对不上）。

另加：`robots` meta（含 `max-image-preview:large`）、`apple-touch-icon`。

### 3. 分享卡片生成（Python + Pillow）

Node 侧没有可用图像库，不值得为此引依赖，改用 Python：
`scripts/gen-og.mjs` 组织数据 → `scripts/gen-og-image.py` 绘制。

产出 `docs/public/og.png`（站点默认）、`docs/public/og/<类别>-<文集>.png`
（23 张，副标题直接取该文集首页的引言）、`apple-touch-icon.png`（180×180）。
**卡片缺失时自动回退 `/og.png`**，所以漏跑脚本不会让构建失败。

版式：纸白底 `#FAF7F2` + 鲁迅红 `#8B2E2E`（与 favicon 同色），
右侧低透明度大字「魯」向右出血，标题用宋体（`STSONG.TTF`）取书卷气，
辅助文字用微软雅黑。累计约 1.1 MB。

### 4. 又一处重复 `<h1>`：关于页

`ArticleTitle.vue` 原先只判断 `endsWith('index.md')`，
但 `about.md` 是 `docs` 根级页面、正文自带 `# 关于本站`，于是也有两个 `<h1>`。

改为**按路径判断**：只有 `<类别>/<文集>/<篇名>.md` 这种「目录下的文章」
才接管标题；首页/自定义页、文集 `index.md`、根级独立页一律跳过。
另支持 `articleTitle: true|false` 覆盖。

（试过用 `layout: page` 绕过 —— **不行**：`VPPage` 里的 `<Content>` 不带
`vp-doc` 类，会让该页丢掉全部中文排版。用 `sidebar: false` + `aside: false`。）

### 5. 发现并修正字数口径错误（重要）

`gen-stats.mjs` 原先用 `.replace(/\s/g,'')` 计字，**把 Markdown 标记也算了进去**：
`#`、`>`、`-`、`[[链接]]`、`<br>`、`<p class="...">` 全算。
而文章页显示的 `frontmatter.chars` 走 `loadMeta()`，会剥掉 frontmatter、
HTML 标签、标题记号 —— 两套口径不一致。

后果：首页与关于页声称 **571 篇 / 168.6 万字**，实际只有 **570 篇 / 135.9 万字**，
虚高约 20%，且各分类偏差不一（散文含大量 `>` 韵文，虚高最多，9.0→6.0 万）。

已把 `gen-stats.mjs` 改成与 `loadMeta()` 完全相同的规则，
并同步修正 `about.md` 的统计表与 `index.md` 的 description。

诊断过程值得记一笔：确认内容没丢，靠的是
`git diff --numstat HEAD -- docs/{novels,prose,essays,academic,letters}`
—— 除已改的 `index.md` 外零差异，说明文章文件与提交版本逐字相同，
问题只在统计口径，不在内容。

### 6. 构建假死（再次遇到，且这次没有 dev server）

同一份代码，隔离副本 87s、主仓库 128s，随后同样的改动连跑三次都卡在
`building client + server bundles`（5～14 分钟，进程 CPU 仅 ~9%，实为等待）。
**已排除**：dev server 冲突（这次已杀掉）、我的 config 改动（钩子在渲染期，
卡在打包期）、残留 build 进程。

**有效做法**：`TaskStop` 掉卡住的构建 → 清空
`docs/.vitepress/{cache,.temp,dist}` → 重跑，冷缓存构建正常。
怀疑是 Vite 的打包缓存被上一次被杀的构建写坏。

**教训**：卡在打包阶段且 CPU 占用很低时，别等，直接清缓存重跑。
